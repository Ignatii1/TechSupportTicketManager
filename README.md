# Заявки (TicketBoard)

Личный трекер заявок [Интрасервиса](https://intraservice.ru) для Windows. Доска из четырёх колонок, живёт в трее,
новая заявка добавляется из любого окна по хоткею: скопировал ссылку в браузере → `Ctrl+Alt+Space` → `Enter`.
Название и статус подтягиваются из Интрасервиса.

Всё хранится локально у тебя на компьютере; в Интрасервис приложение только смотрит (ничего там не меняет).
По желанию — [Claude на claude.ai](#claude) (по подписке, без ключа API) сам ищет и читает заявки через буфер обмена,
а [поиск заявок](#поиск-заявок-и-выгрузка-для-базы-знаний) находит любые заявки по любым условиям и отдаёт их со всей
перепиской — в буфер обмена или файлами Markdown для своей базы знаний в Obsidian и для агента, который её собирает.

## Установка

Нужна Windows 10 или 11 (64-бит). Ставить .NET не нужно — всё внутри одного `TicketBoard.exe`.

1. Скачай `TicketBoard.exe`:
   - со страницы [Releases](https://github.com/Ignatii1/TechSupportTicketManager/releases) — готовые версии;
   - или самую свежую сборку: [Actions](https://github.com/Ignatii1/TechSupportTicketManager/actions) → последний
     зелёный запуск → внизу **Artifacts → TicketBoard** (придёт zip с exe внутри).
2. Положи exe в постоянную папку, например `%LOCALAPPDATA%\Programs\TicketBoard\`. **Рядом с exe будут лежать и данные**,
   поэтому папка должна быть доступна на запись — `Program Files` не подойдёт.
   Не запускай из «Загрузок»: автозапуск запоминает путь к exe, и если его потом перенести — автозапуск перестанет работать
   (тогда просто сними и снова поставь галочку в меню трея).
3. Запусти. При первом запуске Windows может показать «Windows защитил ваш компьютер» — приложение не подписано
   сертификатом. Нажми **Подробнее → Выполнить в любом случае**. Если не помогает — см.
   [Windows не даёт запустить](#windows-не-даёт-запустить).

Обновление: закрой приложение (трей → «Выход») и замени exe новым. Заявки и настройки лежат отдельно и не пропадут.

## Первый запуск

- Откроется доска и появится значок в трее (у часов; если его не видно — он в скрытых значках под стрелкой `^`,
  его можно перетащить на панель задач).
- Крестик окна **не закрывает** приложение, а прячет его в трей — хоткей продолжает работать. Выйти совсем: трей → **Выход**.
- Трей → **Запускать вместе с Windows** — стартует свёрнутым в трей.
- Трей → **Настройки…** — укажи адрес Интрасервиса, логин и пароль (см. [Интрасервис](#интрасервис)).
  Без них всё работает, просто название заявки придётся вводить самому.

## Доска

| Колонка | Для чего |
|---|---|
| **Входящие** | новые заявки — сюда падает всё из быстрого добавления |
| **В работе** | то, чем занят сейчас. Больше лимита (по умолчанию 5) — счётчик жёлтый и пометка «перегруз» |
| **Ждёт ответа** | ждёшь пользователя, подрядчика, запчасть… |
| **Готово** | сделано. Старше 7 дней по умолчанию скрываются (переключатель в верхней панели) |

На карточке: номер заявки, сколько дней она лежит в этой колонке, название, под ним — сервис и организация инициатора,
приоритет (Низкий / Средний / Высокий), число заметок, скрепка с числом вложений и кнопка ↗ — открыть заявку в
Интрасервисе. Синий значок с облачком и числом — **новые комментарии**:
в заявке написал кто-то, кроме вас, после того как вы последний раз смотрели её переписку (см. «Автообновление»).

**Возраст.** Счётчик дней сбрасывается при переносе в другую колонку. За день до порога бейдж жёлтый, на пороге
(по умолчанию 3 дня) — красный, и карточка получает красную рамку: «застряла». В «Готово» не подсвечивается.

**Перенос:** перетащить мышью, стрелки `←` `→`, выпадающий «Статус» в панели деталей или правая кнопка по карточке.

**Поиск и фильтр** (верхняя панель): поиск по номеру, названию, описанию, ссылке и заметкам; фильтр по приоритету.

**Поиск в Интрасервисе.** `Enter` в поле поиска открывает окно [«Поиск заявок»](#поиск-заявок-и-выгрузка-для-базы-знаний)
со словом из поля и сразу ищет на сервере. Интрасервис ищет и по полям заявки, и по тексту всех комментариев, поэтому так
находится и то, чего на доске никогда не было — например, по фразе, которую кто-то написал в переписке полгода назад.
В окне то же, что и из заголовка доски: условия (статус, сервис, исполнитель, даты…), просмотр, копирование, выгрузка;
↗ или двойной клик — открыть заявку в браузере, «+ На доску» — завести карточку (название подтянется из Интрасервиса).

## Импорт моих заявок

Трей → «Импорт моих заявок» или кнопка со стрелкой вниз в верхней панели (рядом с шестерёнкой). Приложение спрашивает
у Интрасервиса, кто вы, какие бывают статусы, и забирает **открытые** заявки, где вы исполнитель. Все они попадают
во «Входящие» — дальше разбираете сами.

- Закрытыми считаются статусы с признаками «Заявка выполнена» и «Конечный», а также перечисленные в настройке
  `ClosedStatusNames` (по умолчанию: Выполнена, Ожидание ответа с автозакрытием, Закрыта, Отменена). Если что-то
  закрытое всё-таки приехало — посмотрите статус на карточке и допишите его название в этот список.
- Импорт можно запускать сколько угодно раз: заявка, которая уже на доске, не добавляется второй раз, не переезжает
  в другую колонку и не теряет заметки и приоритет.
- За один раз забирается не больше 2000 заявок. Если их больше, приложение скажет об этом — запустите импорт ещё раз.
- Ничего не записывается в Интрасервис: импорт только читает.

**Обновить статусы** (`F5` или трей). Импорт только добавляет — сами карточки после него не обновляются, и заявка,
закрытая в Интрасервисе днём, так и висела бы «В работе». `F5` перечитывает с сервера все карточки с номером (кроме
«Готово»): статус Интрасервиса, а ещё название, если оно было автоматическим «Заявка #N», и пустое описание (и
описание, обрезанное версией до 0.15.1: она теряла текст между знаками «<» и «>» — такое чинится один раз, а
поправленное вами не трогается). Если
какие-то из них там уже закрыты — по тому же правилу, что и импорт, с `ClosedStatusNames`, — приложение спросит,
перенести ли их в «Готово». Без вашего «Да» ничего не переносится; ответили «Оставить» — об этих карточках больше не
спросят, пока их статус в Интрасервисе не сменится. Пока идёт импорт или обновление, это написано в
заголовке окна.

**Автообновление** (по умолчанию раз в 5 минут, Настройки → «Автообновление, минут», 0 — выключить). Пока приложение
в трее, оно само делает то же, что импорт и `F5`, только без окон:
- заявка, которую назначили на вас, появляется во «Входящих» — с уведомлением в трее; щелчок по нему открывает доску;
- статусы карточек обновляются сами, по тем же правилам, что у `F5`;
- если заявку с доски закрыли в Интрасервисе — уведомление «Заявка закрыта в Интрасервисе»; щелчок по нему задаёт тот же
  вопрос, что `F5`: перенести ли её в «Готово». Само автообновление в «Готово» ничего не переносит. Уведомление — один раз, когда
  заявка закрылась (в том числе пока компьютер был выключен); пропустили его — не повторяется, но такие карточки
  (кроме оставленных) считает заголовок доски: «закрыты в Интрасервисе: 2 — F5»;
- если в заявке с доски кто-то, кроме вас, написал комментарий — на карточке появляется синий значок с числом новых,
  и приходит уведомление с началом комментария; щелчок открывает эту заявку. Значок гаснет, когда вы посмотрели
  переписку карточки на доске (открыли карточку; если она уже была открыта — щёлкнули или нажали клавишу в окне доски)
  или сами ответили в Интрасервисе. Пока доска в трее, свёрнута или за другими окнами, значок остаётся. Переписка перечитывается только у заявок, которые менялись,
  до 10 за раз; то, что было написано до появления карточки на доске или до версии 0.8.0, новым не считается;
- если заявку, которая лежит в «Готово», **открыли снова** (или снова назначили на вас) — карточка сама возвращается во
  «Входящие», с уведомлением «Заявку открыли снова». Это и частый случай «перенёс в «Готово» заранее, заявка
  закрылась сама, а заявитель её переоткрыл». Перенесли её обратно в «Готово» сами — там она и останется;
- если заявку с доски **передали другому** (вы больше не исполнитель, а она открыта) — уведомление «Заявка больше не
  на вас» с тем, кто теперь исполнитель. Карточка остаётся на доске: её можно доследить или удалить;
- если карточка в «Ждёт ответа», а в заявке **ответил инициатор** — карточка сама возвращается «В работу», с уведомлением
  «Ответ инициатора в #N» и его словами. Комментарий коллеги или системы её не трогает (только значок), закрытую заявку
  («спасибо, можно закрывать») и переданную другому — тоже. Ответ, который вы уже прочитали в открытой карточке, — ваше
  решение: карточка остаётся, где была;
- в заголовке доски видно «обновлено 12:05» или «не удалось обновить» (причина — в `errors.log`).

Автообновление добавляет только **новые** назначения: всё, что было открыто на вас до его первого запуска, приносит
импорт. И не возвращает заявку, которую вы удалили с доски, пока она открыта. Вернуть её — импортом или быстрым
добавлением по номеру. Сменили в настройках адрес или логин — автообновление начинает заново, как в первый раз.

## Быстрое добавление

`Ctrl+Alt+Space` из любой программы (хоткей меняется в настройках) — маленькое окно поверх всех.

- Если в буфере обмена ссылка на заявку — она уже вставлена. Иначе вставь ссылку, номер (`702180` или `#702180`)
  или просто текст. Голый номер распознаётся, только если в поле нет ничего кроме него.
- Номер распознан — появится плашка `#702180` с галочкой и рядом название заявки из Интрасервиса.
- `1` / `2` / `3` — приоритет Низкий / Средний / Высокий. Работает, пока в поле распознанная ссылка; в пустом поле и в
  обычном тексте цифры печатаются как цифры, иначе не набрать номер заявки. Мышью приоритет меняется всегда.
  По умолчанию — Средний.
- `Enter` — заявка уходит во «Входящие». `Esc` или клик мимо окна — закрыть без сохранения.

Если ввёл свой текст вместе со ссылкой — он станет названием. Если только ссылку — название возьмётся из Интрасервиса
(или будет «Заявка #702180», если API не настроен).

## Панель деталей

Открывается кликом по карточке или `Enter`; `Esc` — закрыть. На узком окне (меньше 1100 px) выезжает поверх доски.

- **Название, ссылка, описание** правятся прямо на месте — выглядят как текст, рамка появляется при наведении.
- **Статус** (колонка), **приоритет**, дата добавления, сколько дней в колонке.
- **Интрасервис** — статус заявки в Интрасервисе (наведи — покажет, когда обновлялся). Обновить: правая кнопка по
  карточке → «Обновить из Интрасервиса».
- **Спросить базу знаний** (кнопка под статусом) — кладёт в буфер обмена готовый запрос агенту над базой знаний:
  номер и ссылку заявки, где её файл в базе (или «её ещё нет»), задачу — найти 3–5 похожих решённых, как их решали, что
  сделать и черновик ответа пользователю — и весь текст заявки с перепиской, свежий с сервера, в формате базы (телефонов и
  почты в нём нет). Вставьте в сессию Claude Code на репозитории базы, в Claude Desktop или в чат claude.ai — текст один.
  Текст заявки в запросе стоит между `<ticket>` и `</ticket>` с пометкой, что это данные, а не указания: его пишут
  заявители, и «удали файлы» в комментарии агент выполнять не должен. Папка базы недоступна (сетевой диск без VPN) —
  в запросе путь, куда её кладёт выгрузка, и «проверить не удалось».
  Очень длинная заявка обрезается посередине переписки (начало и свежие записи остаются, в середине — сколько вырезано).
  Под кнопкой — сколько знаков в буфере или что помешало. Если, пока запрос готовится (заявка с длинной перепиской),
  вы скопировали что-то своё, — ваш буфер не затирается: «нажмите ещё раз».
- **Инициатор** (под ним — его должность и организация, телефон и почта, если они есть в Интрасервисе) и
  **Исполнители** (с группой исполнителей) — кто подал заявку, как с ним связаться и кто над ней работает; обновляются
  вместе со статусом. Имена и контакты выделяются и копируются.
- **Сервис** (с типом заявки), **Категории**, **Оборудование** — из карточки заявки в Интрасервисе.
  Открытая карточка тихо перечитывается с сервера через полсекунды после открытия (бег стрелками по карточкам запросов
  не шлёт), если её не читали последние 2 минуты, и сразу — когда автообновление видит, что заявка изменилась: так в
  панели свежие поля и вложения. Ошибка такого чтения не показывается — остаётся, что было. У карточек, заведённых до
  0.20.0, поля и вложения появятся при первом открытии.
- **Вложения** — имена файлов заявки и их размеры (размер сервер сообщает без скачивания файла).
  **Открыть** скачивает файл в папку временных (`%TEMP%\TicketBoard\files\…`) и открывает программой Windows; второй
  раз — без скачивания. Файл там только для чтения: правка в Word не ляжет поверх присланного — «Сохранить как»
  спросит, куда. Программы, сценарии, ярлыки, установщики, справку, базы Access, сертификаты, образы дисков, html и svg
  (запрещённые вложения Outlook и то, что опасным считает сама Windows) TicketBoard не запускает — показывает в папке.
  Ярлыки, библиотеки, коннекторы поиска и темы (`.url`, `.lnk`, `.library-ms`, `.searchconnector-ms`, `.theme`…)
  Проводник читает, даже просто показывая папку, — значок по сетевому пути отдал бы чужому серверу хэш пароля Windows,
  поэтому такие файлы ложатся с `_` в конце имени (`отчёт.url_`): это просто файл, его можно открыть Блокнотом.
  **Сохранить** спрашивает, куда (имя — исходное, без знаков, которых Windows не допускает), и кладёт туда скачанное или
  скачивает. Скачанное помечается «из интернета», как браузером: Office откроет документ в защищённом просмотре, Windows
  предупредит про программу; диск, который пометку не хранит (флешка FAT, иногда сетевой), — сказано в строке
  вложения. Там же ход скачивания, ошибка («не скачалось: …») или куда сохранено. Сбой сети и ответы 5xx повторяются
  сами (через 2, 5 и 15 с). Невидимые знаки направления текста из имён убраны: имя «счёт», знак RLO, «fdp.exe»
  не выдаст себя за `счётexe.pdf`.
- **Заметки** — поле внизу, `Enter` сохраняет с текущим временем. Новые сверху. Крестик справа в строке (появляется
  при наведении) удаляет заметку — без подтверждения.
- **Переписка** — комментарии из Интрасервиса по этой заявке: кто, когда и что написал. Только чтение, в файлы не
  сохраняется. Плашка «внутр.» — комментарий не виден заявителю, плашка со статусом — на этой записи статус поменялся.
  Записи без комментария (просто смены статуса) спрятаны, кнопка-глаз их показывает; ⟳ перечитывает переписку с сервера.
  Открытая переписка обновляется сама: после захода автообновления (и ваши собственные комментарии, написанные в
  браузере), после F5 и после ⟳ карточки. Если в заходе что-то поменялось, а переписка та же, список не перестраивается —
  прокрутка и выделенный текст на месте.

## Клавиатура

| Клавиша | Действие |
|---|---|
| `Ctrl+Alt+Space` | быстрое добавление из любого окна (глобальный хоткей) |
| `N` или `Ctrl+N` | быстрое добавление с доски |
| `/` или `Ctrl+F` | поиск по доске |
| `Enter` в поиске | открыть «Поиск заявок» со словом из поля и искать на сервере — по заявкам и по тексту их комментариев |
| `↑` `↓` | выбрать карточку в колонке |
| `←` `→` | перенести выбранную карточку в соседнюю колонку |
| `1` `2` `3` | приоритет выбранной карточки: Низкий / Средний / Высокий |
| `Enter` | открыть / закрыть панель деталей |
| `Esc` | выйти из поля ввода (в поиске — ещё и очистить) → закрыть панель → снять выделение |
| `F5` | обновить статусы всех карточек из Интрасервиса и предложить убрать закрытые в «Готово» |
| `Ctrl+Del` | удалить выбранную заявку с доски (спросит: `Enter` — удалить, `Esc` — отмена; в Интрасервисе она останется) |
| двойной клик | открыть заявку в Интрасервисе |

- Жёлтая точка в правом верхнем углу — «В работе» больше лимита.

- Правый клик — меню: Открыть · Быстрое добавление · **Импорт моих заявок** · **Обновить статусы** · **Поиск заявок и
  выгрузка…** · Запускать вместе с Windows · Открыть папку с данными · Настройки… · Выход.

## Интрасервис

Приложение читает заявку из Интрасервиса по номеру через его REST API (`GET {адрес}/api/task/{номер}`).
У API Интрасервиса нет отдельных токенов — вход по твоим обычным **логину и паролю**.

Настройка: трей → **Настройки…** → адрес (например `https://helpdesk.company.ru`), логин, пароль →
**Проверить подключение** → **Сохранить**.

Что происходит дальше:
- в быстром добавлении рядом с номером видно название заявки;
- у новой заявки заполняются название (если ты не ввёл своё), описание (если пустое или обрезано версией до 0.15.1) и
  статус в Интрасервисе;
- правая кнопка по карточке → **Обновить из Интрасервиса** — перечитать статус.

Безопасность:
- Пароль хранится зашифрованным средствами Windows (DPAPI): расшифровать его может только твоя учётная запись на этом
  компьютере. На другом компьютере пароль придётся ввести заново.
- Используй адрес `https://`. По `http://` пароль уходит по сети открытым текстом — приложение предупредит.
- Вводи адрес сразу с `https://`: если сервер перенаправляет с http на https, пароль по дороге теряется и будет
  ошибка «неверный логин или пароль».

> Работа с API написана по документации IntraService API v5.42 и ещё не проверялась на живом сервере.
> Если вместо названия видишь ошибку — пришли её текст.

## Claude

Claude в чате на claude.ai (обычная подписка Pro, без ключа API) может сам искать заявки в Интрасервисе, читать их
переписку и твою доску. Например: «были ли раньше проблемы с принтером в бухгалтерии и как их решали?», «что у меня
висит дольше всех и что там последнее?», «коротко: что в заявке 702180 и что ответить пользователю?».

Как это устроено. Claude на claude.ai не может обратиться к твоему компьютеру, а TicketBoard не ходит в интернет.
Поэтому данные носит буфер обмена: когда Claude нужны данные, он пишет блок запросов вида

```
TB search принтер бухгалтерия
TB history 702180
```

Ты жмёшь **Copy** на этом блоке — TicketBoard (он в трее) замечает запросы в буфере, выполняет их в Интрасервисе и на
доске и кладёт в буфер ответ, о чём говорит уведомление «Ответ для Claude — в буфере». Остаётся `Ctrl+V` и `Enter` в
чате. Claude может попросить ещё — и так пока ему не хватит данных. Изменить что-либо в Интрасервисе он не может.

Настройка (один раз):
1. Трей → **Настройки…** → раздел **Claude** → галочка **Отвечать на запросы Claude через буфер обмена** → **Сохранить**.
2. Там же **Скопировать инструкцию для Claude**. На claude.ai создай проект (например «Заявки») и вставь инструкцию
   в его инструкции (Project instructions). Чаты в этом проекте уже знают, как просить данные. Без проекта — вставь
   инструкцию первым сообщением в чат.

Запросы, которые понимает TicketBoard (их пишет Claude, но можно и самому — скопировать такой текст):

| Запрос | Что вернёт |
|---|---|
| `TB search <слова>` | поиск по полям заявок и всем комментариям: до 20 самых свежих совпадений со ссылками |
| `TB ticket <номер>` | заявка: название, статус, инициатор и исполнители, описание, ссылка; если она на доске — колонка, приоритет, твои заметки |
| `TB history <номер>` | переписка и смены статуса, свежие сверху, до 50 записей; внутренние комментарии помечены |
| `TB board` | твоя доска по колонкам («Готово» старше срока скрытия — только числом) |

До 10 строк за раз. Длинный ответ claude.ai сам превращает во вложение — так и задумано.

Что стоит знать:
- В буфер TicketBoard смотрит, только пока стоит галочка, и отвечает лишь на текст, где каждая строка начинается
  с `TB` (заглавными) и есть хоть один понятный запрос. Всё остальное пропускает и нигде не хранит, а скопированное
  из менеджеров паролей, таблиц Office и файлы даже не читает.
- Если, пока собирается ответ, ты скопировал что-то другое, TicketBoard это не затрёт — скажет уведомлением, что ответ
  не вставлен. Скопировал следующий блок `TB` — выполнит его следом.
- Ответ уходит в Claude, как если бы ты вставил заявки руками. В настройках claude.ai (Privacy) реши, можно ли
  использовать твои чаты для обучения моделей.
- Вставил, а там снова твой блок `TB …` — значит, ответ ещё не был готов: дождись уведомления и вставь ещё раз.

## Поиск заявок и выгрузка для базы знаний

Окно **Поиск заявок** ищет на сервере Интрасервиса любые заявки, которые видит твоя учётная запись (не только свои), по
любому сочетанию условий; показывает найденное, текст выбранной заявки в том виде, в каком он уйдёт агенту, и отдаёт его
дальше — в буфер обмена (вставить в чат Claude) или файлами Markdown для базы знаний в Obsidian. Открывается кнопкой в
заголовке доски (документ с лупой), из трея (**Поиск заявок и выгрузка…**) и по `Enter` в поле поиска на доске — тогда
со словом из поля и сразу с поиском; остальные условия при этом по умолчанию, а запомненные («привычные») такой поиск
не перезаписывает — когда окно потом откроют из трея заново, в нём снова привычные условия.

- **Условия.** Склеиваются по «И»; пустое — не условие. Что запоминается — окно откроется с теми же условиями.
  - **Слова** — их ищет сам Интрасервис, в полях заявки и во всех комментариях; не меньше 3 символов.
  - **Исполнитель** — «Я» и (или) часть фамилии; **Заявитель** — часть фамилии. Фамилию программа ищет в справочнике
    сотрудников: нашёлся один — берёт его; несколько (до 10) — ищет по всем и над списком пишет, по кому именно; никого
    или больше 10 — просит уточнить. Справочник сотрудников виден не каждой роли — тогда здесь будет «нет доступа».
  - **Статус** — любой, «Закрытые» (в них решение), «Открытые» или один из статусов сервера. Закрытые — по признакам
    статуса и списку `ClosedStatusNames`, как у `F5`.
  - **Сервис** — вместе с вложенными или только он сам; **Тип заявки**. Весь список сервисов Интрасервис отдаёт не каждой
    учётной записи (нужно право на просмотр списка сервисов). Тогда в списке — сервисы, на которые вы назначены, а если
    нет и их — сервисы последней 1000 заявок (вложенные тогда — только те, что есть в списке); под списком написано, какой
    случай и почему. Не загрузилось ничего — под списком причина; сервис тогда задаётся сохранённым фильтром. Запомненный
    сервис, которого в таком списке нет (или список не загрузился), остаётся выбранным — строкой «Сервис №…», и поиск идёт
    по нему (вложенные тогда не берутся — над списком об этом сказано). Какие списки не загрузились (статусы, типы, фильтры) —
    вверху условий.
  - **Создана**, **Изменена**, **Закрыта** — «с … по …», `дд.мм.гггг` (год 2000–2100), оба дня целиком; любую границу можно
    не задавать.
  - **Сохранённый фильтр** — фильтры из веб-интерфейса Интрасервиса. Чего нет в окне (группа исполнителей, категории,
    сроки…), собирается там один раз и выбирается здесь; остальные условия действуют поверх него.
  - **Архивные и неактуальные сервисы** — галочка по умолчанию стоит; без неё сервер заявок таких сервисов не отдаёт
    (а в базу знаний нужна и старая история).
- **Список.** Сверху — сколько найдено; по 50 заявок, «Показать ещё» (в окне — до 1000, остальное уточнением условий или
  выгрузкой файлами). «Найдено: 1 000+» — сервер считает совпадения только до тысячи: их тысяча или больше, сколько точно —
  неизвестно (выгрузка всё равно берёт все). В строке: номер, статус, сервис · тип, название, автор, исполнители, даты. ↗ или двойной клик —
  открыть в браузере, «+ На доску» — завести карточку (с номером, ссылкой и названием из найденного); заявка, которая уже на
  доске, помечена. Выбирать можно несколько (`Ctrl`, `Shift`).
- **Просмотр.** Ниже списка — текст выбранной заявки: тот самый Markdown, который попадёт в файл или в буфер обмена.
  **Копировать** кладёт в буфер выбранные заявки подряд (до 30 за раз — больше в чат всё равно не поместится): вставь
  в чат с агентом.
- **Выгрузка в файлы** — для базы знаний. Папка по умолчанию `knowledge` рядом с exe; можно выбрать папку в хранилище
  Obsidian — файлы появятся прямо там. «Выгрузить найденные» берёт всё найденное по этим условиям, но не больше «Не больше,
  заявок»: число (по умолчанию 500; на кнопке видно «500 из 1 200», когда найдено больше) или **0 — все, сколько бы ни
  нашлось** (потолка сверху нет). Поиску это поле не мешает. «Выгрузить выбранные» — только выбранное в списке. Кнопка
  «найденные» ждёт нового поиска, если условия поменяли после него. Папку окно запоминает, только когда в неё лёг первый
  файл заявки: папку не создать (опечатка в пути) — «Не удалось записать в папку …», файлы не ложатся (диск только для
  чтения) — «Не выгружены: N» с первой ошибкой «файл не записан: …»; в обоих случаях папка в настройках прежняя.
- **Папки.** Заявки раскладываются по месяцу создания: `tickets\2026-08\702180 — Название.md` (без даты создания —
  `tickets\без даты\`). В папке месяца — свой `_index.md` со списком её заявок, в корне — общий `_index.md` по месяцам и
  пояснение формата для агента. Файлы, выгруженные версиями 0.10–0.12 (все прямо в `tickets\`), при первой же выгрузке сами
  переезжают в папки месяцев — без запросов к серверу. Свои заметки лучше держать вне `tickets\`: выгрузка переписывает и
  убирает (старое имя заявки, дубли) только файлы со свойством `source: intraservice`, а чужие — заметку, чьё имя начинается с
  номера заявки, испорченный файл, свои папки среди месяцев — не трогает. Исключение одно: файл с точно тем именем, под каким
  ляжет заявка (`702180 — Название.md` в её месяце), будет перезаписан.
- **Формат** — Markdown. В начале файла свойства: номер, статус, даты (создана, изменена, решена, закрыта), сервис,
  тип, категории, оборудование, инициатор и его организация, исполнители и группа, число вложений, ссылка — и что видно
  по истории: участники (кто писал и менял статус, по числу действий), твоя роль (исполнитель, инициатор или участник),
  часы до первой реакции и до решения, сколько раз переоткрывали, сколько комментариев (публичных и внутренних) и
  закрывающий комментарий (у закрытой — последний публичный не от инициатора, до 300 знаков; обычно в нём решение).
  Дальше описание и переписка по времени — от первой записи к
  последней; внутренние комментарии помечены «(внутренний)», смена статуса — «статус «…»». Телефоны и почта из карточек
  людей в файлы и в буфер не попадают (в тексте описаний и комментариев — как написано). **Пароли скрыты**: после
  «пароль:», «password=», «pwd:», «пин-код:» (и в начале следующей строки, как в форме «Пароль:⏎12345») значение
  заменено на `[скрыт]` — в файлах, их именах, таблице, «Спросить базу знаний» и ответах Claude через буфер; логин
  остаётся. «Пароль 12345» без двоеточия не распознаётся — такое правило испортило бы обычный текст. Панель доски
  показывает переписку как есть. Текст заявок пишут люди со
  стороны, поэтому в файле он только текст: html, команды плагинов Obsidian (Templater `<%`, DataviewJS `$=`, блок кода
  в цитате или пункте списка) и комментарии Obsidian `%%` в нём не сработают — в файле они записаны сущностями html
  (`&lt;`, `&#36;`, `&#37;`). В тексте Obsidian показывает их обычными знаками (а xml из заявки теперь виден, раньше его
  съедало как html), в коде — строках с отступом от 4 пробелов и `` `…` `` — как записаны. Ссылки вида
  `<https://…>` и `<почта@домен>` остаются ссылками. В `_index.md` — список всех выгруженных заявок и пояснение формата
  для агента (там же — что значат эти сущности). Знаки «<» и «>» в тексте заявки (остаток < 5, коды маркировки) — это
  текст: до 0.15.1 выгрузка принимала кусок между ними за html-тег и теряла его. Описание или комментарий в html (из
  редактора или письма) выгружается видимым текстом — как его показывает браузер. Формат файла сменился в 0.15.1 (версия 4):
  следующая выгрузка «все» перепишет все файлы.
- **Повторная выгрузка** — одной кнопкой: окно помнит условия и папку. Изменившиеся заявки переписываются, остальные
  пропускаются без запросов к серверу; переименованная заявка пишется новым файлом вместо старого. Не прочитавшиеся
  (сервер не отдал карточку заявки или переписку) дочитаются в следующий раз. Сервис и тип сервер отдаёт только в карточке
  заявки, поэтому у каждой изменившейся заявки читаются и карточка, и переписка.
- **Выгрузить все заявки**, какие видит учётная запись (для разбора потом). «Сбросить» (снимает «Я» и все условия — над
  списком появится «Условий нет: ищу среди всех заявок…»), «Найти», в «Не больше, заявок» — `0`, «Выгрузить найденные».
  От 2000 заявок программа сначала спросит. Дальше:
  - Заявки читаются страницами по 200 и сразу пишутся файлами, в памяти — страница списка и имена уже лежащих файлов
    (около сотни байт на файл): сто тысяч заявок не проблема.
    Список идёт по дате создания, от старых к новым, — порядок не «едет», пока выгрузка работает часами. На заявку нужен
    1–2 запроса (карточка и переписка), по 4 разом, поэтому на десятках тысяч заявок это часы; под кнопками видно «Выгружено
    1250 из 98000 · осталось ~3 ч 12 мин». «Выгружено» — сколько заявок легло файлами (записаны или не менялись); не
    выгруженные — отдельно: «· не выгружено 3». Если сервер досчитал только до тысячи («Найдено: 1 000+»), сколько всего,
    неизвестно: тогда «Выгружено 1250 · ~40 в минуту», а вопрос перед выгрузкой — без числа. Не давай компьютеру уснуть. Окно можно
    закрыть — выгрузка идёт.
  - **Сверка вторым проходом.** Список читается страницами, и сервер на стыке страниц иногда отдаёт заявку дважды, а
    соседнюю теряет (при одинаковых датах создания), или список укорачивается за время выгрузки (заявку передали, закрыли
    от вас) и одна проскакивает. Поэтому, если первый проход недосчитался, повторял заявки или найдено «1 000+», выгрузка
    читает список ещё раз, в другом порядке («Сверяю список вторым проходом…»), и выгружает пропущенное. Так же и с пределом
    («Не больше, заявок»), если все найденные в него умещаются (сервер насчитал не больше предела); нашлось больше, чем
    осталось мест (список вырос за время выгрузки), — выгружаются самые свежие из найденных, и итог говорит, сколько
    осталось за пределом (это не ошибка: выгружено столько, сколько просили; нужны все — поднимите предел). В итоге
    «Второй проход по списку нашёл заявок, которых не было в первом: N…». Если и так не хватает до счёта сервера одной-двух —
    «Сервер насчитал N, а разных заявок в списке M…»: значит, сервер считает какую-то заявку дважды или её удалили либо
    скрыли за это время; выгружено всё, что есть. Пришла одна и та же заявка дважды в обоих проходах — итог называет её
    («заявка #N пришла в списке дважды»): сервер, похоже, её и посчитал дважды. Не хватает больше — «Список закончился раньше… и второй проход недостающих
    не нашёл», выгрузка не закончена: пришли этот итог.
  - **Файлы, пропавшие после записи.** В конце выгрузка проверяет, что записанные файлы на месте. Нет каких-то —
    «Записано, но уже нет на диске: N (#…)»: обычно это антивирус, который по содержимому переписки отправляет файл в
    карантин. Посмотри его журнал («Безопасность Windows» → «Журнал защиты» или карантин корпоративного антивируса),
    добавь папку выгрузки в исключения и выгрузи снова — недостающие запишутся.
  - **Остановить и продолжить.** «Остановить» (а также закрытое приложение, обрыв сети, перезагрузка) оставляет всё,
    что записано; следующая выгрузка с теми же условиями пропускает готовые и не менявшиеся заявки — без запросов к
    серверу, только список страниц — и продолжает с того же места. Так же дозагружается то, что изменилось, пока шла
    выгрузка. Оглавления месяцев пересобираются в конце (и после остановки); файлы можно читать, пока идёт выгрузка.
  - **Сбои.** Сервер не ответил, соединение оборвалось, ответ 5xx — запрос повторяется (через 2, 5 и 15 секунд; на ошибку 500
    — один повтор: чаще это «битая» заявка, чем сбой); не помогло — заявка «не прочиталась» и дочитается в следующий раз.
    Выгрузка сама прерывается, если сервер не принимает логин и пароль (401), 30 заявок подряд не прочитались из-за сети или
    сервера (100 — если сервер отвечает ошибкой 500), 25 заявкам сервер отказал, а не легла ещё ни одна (нет доступа к
    карточкам) или файлы
    не записываются (диск полон, путь слишком длинный). Что успели, остаётся; причина — под кнопками. Название файла
    укорачивается, если путь к папке выгрузки такой длинный, что иначе не влез бы в 260 знаков Windows.
- Выгрузка идёт в фоне: окно можно закрыть, «Остановить» сохраняет то, что успели. Сервер нагружается умеренно — по
  4 запроса разом.
- Если сервер, похоже, не применил условие по дате создания или изменения (формат даты в запросе проверен не на каждом
  сервере), окно предупредит, что в списке лишнее, а выгрузка такие заявки пропустит. Если он не принял сортировку по
  дате создания, выгрузка всех пойдёт по дате изменения и скажет об этом: заявки, тронутые за время выгрузки, могли не
  попасть — запусти её ещё раз.

### Таблица заявок, SCHEMA.md и CLAUDE.md

После каждой выгрузки (из окна поиска и автовыгрузки) в корне папки выгрузки лежат:

- **`tickets.csv`** — все выгруженные заявки, строка на заявку, колонки по смыслу: что (номер, название, сервис, тип,
  категории, оборудование), кто просит (инициатор, организация), кто решает (группа, исполнители, участники, твоя роль),
  когда и как быстро (статус, даты создания, изменения, решения и закрытия, часы до реакции и до решения — с запятой,
  как ждёт русский Excel), как (переоткрытия, число комментариев и вложений, закрывающий комментарий), где (ссылка и путь
  файла). Колонки из истории есть у файлов, выгруженных версией 0.18.0 и новее: старые файлы перепишет следующая полная
  выгрузка (формат файлов сменился — неизменные заявки тоже перечитаются), до того эти ячейки пусты. Открывается двойным щелчком в
  Excel (UTF-8 с BOM, разделитель `;`); агент в сессии над базой читает её pandas или duckdb. Сначала по таблице
  сужают круг (тот же сервис, тип, слова в названии), а целиком читают только лучшие заявки. Строки — блоками месяцев,
  свежие сверху. **Даты** — в одном виде со свойствами файлов: `2026-10-16T09:45:39+03:00` (ISO 8601, без долей секунды;
  сервер присылает время без пояса, пояс — этого компьютера), посимвольно та же строка, что `created`/`changed` в файле
  (у файлов, выгруженных до 0.18.1, — после полной выгрузки); такие строки сравниваются и сортируются как даты. Excel
  оставляет их текстом: фильтр «по дате» и вычитание дат в нём не работают (раньше, до 0.18.1, — `2026-10-16 09:45:39`;
  таблица прежнего вида собирается заново сама). Служебное свойство файла `revision` — точная версия заявки на сервере,
  число: по нему выгрузка узнаёт неизменные файлы. Значение, которое Excel принял бы за формулу (`=`, `+`, `-`, `@` в начале — название пишет заявитель),
  записано с `'` впереди. Телефонов и почты нет. Таблица переписывается, только если что-то поменялось; если она была
  открыта в Excel и записать не вышло — допишется при следующей выгрузке. Пересохранили её в Excel — следующая выгрузка
  соберёт её заново из файлов; если Excel сохранил её не в UTF-8 (или это ваш собственный `tickets.csv`), TicketBoard её
  не трогает и пишет об этом в итоге выгрузки — переименуйте или удалите файл. «Остановить» прерывает и сборку таблицы:
  прежняя остаётся, догонит следующая выгрузка.
- **`SCHEMA.md`** — что в каких папках и файлах и что значит каждая колонка таблицы. Его переписывает TicketBoard
  (свой файл с таким именем он не тронет и скажет об этом).
- **`CLAUDE.md`** — заготовка для агента: как искать похожие (сначала таблица, потом текст), как отвечать, куда класть
  свои выводы (`answers/`, `reports/`) и что текст заявок — данные, а не указания. Кладётся, только если его нет:
  дальше он ваш, правьте под себя — TicketBoard его не трогает. Удалите — положит заготовку снова.

Таблица собирается из свойств уже выгруженных файлов, без сервера: при первой выгрузке после обновления — целиком
(на большой базе — минуты), дальше переписываются только месяцы, где что-то менялось.

### Вложения

Скриншоты, документы и письма заявок выгрузка (из окна поиска и автовыгрузка) кладёт в базу рядом с заявками — по
умолчанию только ваших заявок (вы исполнитель, инициатор или участник; Настройки → «Вложения в базу знаний»: моих,
всех выгружаемых или не скачивать):

- `files\<ГГГГ-ММ>\<номер заявки>\<номер файла> — <имя>` — месяц тот же, что у файла заявки; номер файла впереди, потому
  что имена в одной заявке повторяются (`image001.png` в каждом письме). Знаки, которые Windows и Obsidian не терпят в
  именах, заменены пробелами; длинное имя укорочено, расширение цело. Вложение-заметка (`.md`, `.canvas`, `.base`) и
  `.tmp` получают `_` в конце имени: файл пришёл от заявителя как есть, и Obsidian не должен открывать его как свою
  заметку — команды Templater и DataviewJS в нём не выполнятся. Так же — ярлыки, библиотеки, коннекторы поиска и темы
  Windows (`.url`, `.lnk`, `.library-ms`, `.theme`…): Проводник читает их, даже просто показывая папку базы (с 0.20.0;
  уже выгруженные переименуются, когда их заявку перечитает выгрузка).
- Файлы **от 50 МБ** — в `files-lfs\…`, через Git LFS: GitHub не принимает файлы больше 100 МБ, и один такой коммит
  остановил бы отправку Obsidian Git. Правило `files-lfs/** filter=lfs …` TicketBoard сам дописывает в `.gitattributes`
  папки выгрузки до первого файла. **Один раз** в папке хранилища выполните `git lfs install` (Git LFS входит в Git for
  Windows; есть ли он — `git lfs version`). В облачной сессии без git-lfs вместо таких файлов — короткие текстовые
  указатели.
- В файле заявки — раздел «Вложения» после описания: картинки Obsidian показывает прямо в заметке, остальное — ссылками;
  путь — от корня базы, его же видит агент. «не скачано» — настройка не велит (чужая заявка), «не скачалось: …» —
  сбой: файл заявки записан, а следующая выгрузка перечитает её и попробует снова.
- Скачанное повторно не качается; файл, убранный с заявки, убирается и из папки (в истории git он остаётся); ваши
  файлы без номера впереди в папке заявки не трогаются.
- Итог выгрузки говорит, сколько скачано и сколько занимают `files` и `files-lfs` целиком; в ходе — сколько пришло.
- Просмотр, «Копировать» и «Спросить базу знаний» ничего не качают — там только имена вложений.

Первая полная выгрузка после 0.19.0 переписывает все файлы (формат 7) и качает вложения ваших заявок — может занять
долго, её можно пустить на ночь.

### Автовыгрузка закрытых

Настройки → **«Выгружать закрытые заявки в базу знаний»** (выключена по умолчанию; работает вместе с автообновлением).
При каждом автообновлении закрытые заявки, где ты исполнитель, инициатор или участник (писал комментарий или менял
статус), уходят в ту же папку выгрузки, что у окна «Поиск заявок», в том же формате. Руками ничего запускать не нужно:
закрыл заявку — через несколько минут её файл в базе.

- **Закрытые** — как у `F5`: статусы с признаком «Заявка выполнена» или «Конечный» и названия из `ClosedStatusNames`;
  и по архивным и неактивным сервисам тоже.
- **Изменения после закрытия** (дописали комментарий, «Выполнена» → «Закрыта») — файл перезаписывается.
- **С какого момента.** После включения — то, что менялось за последнюю неделю; раньше — выгрузкой из окна «Поиск
  заявок» (исполнитель и инициатор там — фильтры). Выключил и включил снова — опять с недели назад. Закрытое, пока
  компьютер был выключен или автообновление стояло на 0, выгрузка догоняет сама.
- **Порциями.** За заход — не больше 30 заявок, которым нужен запрос; накопилось больше (выходные, отпуск) — догонит за
  несколько заходов, в подсказке значка в трее при этом «догоняю».
- **Чужие закрытые** (видимые вам, но без вашего участия) читаются, только чтобы это понять: их история запрашивается
  один раз, в базу они не попадают. Исключение — история длиннее 5000 записей: её TicketBoard читает не всю и, чтобы не
  потерять ваше участие в начале, выгружает такую заявку. Заявка без темы (из почты) выгружается как «Заявка #N».
  Телефонов и почты в файлах нет.
- **Сломанная заявка.** Если одна заявка не выгружается (сервер отвечает ошибкой только на неё, к её истории нет
  доступа, антивирус удаляет её файл), каждый заход пробует её снова, а отметка дальше неё не идёт; заявки после неё
  выгружаются. Не далась пять заходов подряд и не меньше часа — пропускается: в подсказке трея «пропущено 1», в
  `errors.log` — её номер и ошибка. Выгрузить её можно руками из «Поиска заявок»; изменится — автовыгрузка попробует
  снова. Сбои сети и неверный логин так не пропускаются — их выгрузка пережидает: в подсказке «не удалось», подробности в
  `errors.log`. Файл не записался: если мешает то, что лежит на месте самого файла (папка с его именем, файл только для
  чтения), — пропуск, как выше; не записался даже временный файл рядом (диск полон, нет доступа) — ждёт. Папку выгрузки
  не создать (диск отключён) — «не удалось», без окон с ошибками.
- **Итог** — в подсказке значка в трее: «база знаний: 12:05, выгружено 3», «новых нет» или «не удалось» (подробности —
  в `errors.log`, по разу на ошибку). Сменили адрес или логин Интрасервиса или папку выгрузки — автовыгрузка начинает
  заново, с недели назад (в новую папку). Папка у автовыгрузки и у окна «Поиск заявок» одна: выгрузили из окна в другую
  папку — итог выгрузки скажет, что автовыгрузка тоже пойдёт туда (отказались от выгрузки на вопросе «Выгрузить
  заявок: …?» — папка не меняется). Перенесли программу с папкой по умолчанию
  (`knowledge` рядом с exe) — это не смена папки. Пока идёт выгрузка из окна «Поиск заявок», автовыгрузка ждёт её конца
  (пишет одна выгрузка за раз, даже в разные папки), и наоборот — окно тогда пишет «Жду: сейчас пишет другая выгрузка…»
  и, дождавшись, «Начинаю…». Остановили, пока ждали, — ничего не записано, и папка в настройках прежняя: окно запоминает
  папку, только когда выгрузка и правда пошла.
- **Git.** Если папка выгрузки лежит в git-репозитории — сама его корень или подпапка (например, хранилище Obsidian,
  которое отправляет в GitHub плагин Obsidian Git), TicketBoard дописывает в `.gitignore` самой папки строку `*.tmp` — до
  первого файла (папки нет — создаёт её), и при выгрузке из окна «Поиск заявок» тоже; удалили `.gitignore` — допишет
  снова: файлы пишутся через временные, и коммит не поймает недописанный. Не дописать (`.gitignore` только для чтения) —
  окно скажет в итоге выгрузки, автовыгрузка — в `errors.log` (каждая причина — один раз). Сам TicketBoard ничего не коммитит.
- **Предел.** Если в одну минуту изменилось больше закрытых заявок, чем сервер отдаёт за раз (по документации — до 2000),
  выгрузка остановится с ошибкой в `errors.log` («…чем сервер отдаёт за раз»). Это известный предел: его снимет чтение
  такой минуты постранично.

## Настройки

Трей → **Настройки…** или шестерёнка в заголовке окна. Ошибки в полях видны сразу; «Сохранить» применяет всё без
перезапуска. Хранятся в `settings.json` рядом с exe (правка руками тоже возможна, применится после перезапуска).

| Настройка | Что делает | По умолчанию |
|---|---|---|
| Глобальный хоткей | открыть быстрое добавление | `Ctrl+Alt+Space` |
| `ClosedStatusNames` (только в файле) | названия статусов, которые импорт считает закрытыми, сверх признаков «Заявка выполнена» и «Конечный» | Выполнена, Ожидание ответа с автозакрытием, Закрыта, Отменена |
| Номер заявки в ссылке | регулярное выражение, группа 1 — номер. Если не совпало — берётся последнее число в ссылке | понимает `…/Task/View/702180`, `#702180`, `№ 702180`. Поле целиком из 4–8 цифр — номер и без регулярки |
| Скрывать «Готово» старше | дней | 7 |
| Лимит «В работе» | больше — подсветка перегруза | 5 |
| Просрочена через | дней в колонке до красного; за день до этого — жёлтый | 3 |
| Адрес, логин, пароль Интрасервиса | для API; пусто — API выключен | — |
| Автообновление, минут | как часто тихо проверять свои заявки: новые — во «Входящие», статусы — на карточки, о закрытых и о новых чужих комментариях — уведомление, ответ инициатора возвращает карточку из «Ждёт ответа» «В работу»; 0 — выключено | 5 |
| `AutoSyncSkipIds` (служебное, в файле) | заявки, которые автообновление не добавляет: удалённые с доски и открытые до его первого запуска. Правится само | — |
| `AutoSyncAccount` (служебное, в файле) | адрес и логин, к которым относится то, что автообновление помнит о ваших заявках; сменили их — всё собирается заново, без лавины уведомлений. Правится само | — |
| Выгружать закрытые заявки в базу знаний | при каждом автообновлении — закрытые, где вы исполнитель, инициатор или участник, в папку выгрузки (см. [Автовыгрузка закрытых](#автовыгрузка-закрытых)) | выключено |
| Вложения в базу знаний | чьи вложения выгрузка кладёт в `files` и `files-lfs` рядом с `tickets`: моих заявок, всех выгружаемых или не скачивать (см. [Вложения](#вложения)) | моих заявок |
| `AutoExportSince`, `AutoExportSeen`, `AutoExportDir` (служебное, в файле) | докуда автовыгрузка разобрала закрытые заявки и для какой папки; сбрасывается при смене адреса, логина или папки выгрузки и при выключении выгрузки. Правится само | — |
| Отвечать на запросы Claude через буфер обмена | скопированный блок `TB …` заменяется ответом (см. [Claude](#claude)) | выключено |
| `KnowledgeDir`, `LastSearch` (в файле, меняются из окна поиска) | папка выгрузки для базы знаний (пусто — `knowledge` рядом с exe) и последние условия поиска | — |

Хоткей пишется через `+`: модификаторы `Ctrl`, `Alt`, `Shift`, `Win` и клавиша — `Ctrl+Alt+Space`, `Ctrl+Shift+T`, `Win+Alt+N`.

## Данные и резервные копии

Всё лежит в одной папке с `TicketBoard.exe` (трей → «Открыть папку с данными»):

| Файл | Что это |
|---|---|
| `tickets.json` | все заявки и заметки. Сохраняется сам через полсекунды после любого изменения |
| `backups\tickets-ГГГГ-ММ-ДД.json` | копия раз в день, хранятся последние 30 |
| `settings.json` | настройки (пароль — только в зашифрованном виде) |
| `errors.log` | ошибки приложения, если были — его можно прислать, чтобы разобраться |
| `knowledge\` | выгрузка для базы знаний, если папка в окне поиска не изменена: `tickets\ГГГГ-ММ\` (заявки и оглавление месяца) и общий `_index.md` |
| `%TEMP%\TicketBoard\files\` | вложения, открытые из панели (не рядом с exe): кэш, не данные — его чистит Windows, удалить можно в любой момент |

- Восстановить из копии: выйди из приложения, замени `tickets.json` нужным файлом из `backups`, запусти.
- Если `tickets.json` испорчен, приложение его не затирает: переименовывает в `tickets.json.corrupt-…` и начинает с пустой
  доски. Данные можно достать из этого файла или из `backups`. С `settings.json` так же: испорченный (например, опечатка
  при правке руками) уходит в `settings.json.corrupt-…`, приложение запускается с настройками по умолчанию и говорит об
  этом уведомлением. Лишняя запятая в конце списка и комментарии `//` порчей не считаются.
- Перенести на другой компьютер (или носить на флешке): скопируй папку с exe целиком — заявки, заметки, настройки и копии
  переедут вместе с ней. Пароль Интрасервиса придётся ввести заново: он шифруется под учётную запись Windows и конкретный
  компьютер, поэтому на новом ПК не расшифруется. Адрес сервера и логин переносятся.
- Если приложение запущено сразу на двух компьютерах из одной синхронизируемой папки (OneDrive и подобные) — кто сохранил
  последним, тот и прав. Лучше держать открытым что-то одно.

## Если что-то не работает

### Windows не даёт запустить
- **«Windows защитил ваш компьютер»** — **Подробнее → Выполнить в любом случае**. Появляется, потому что exe не подписан.
- **Кнопки «Выполнить» нет / файл сразу блокируется** — правый клик по exe → **Свойства** → внизу галочка
  **Разблокировать** → ОК. То же в PowerShell: `Unblock-File "$env:LOCALAPPDATA\Programs\TicketBoard\TicketBoard.exe"`.
- **«Приложение заблокировано администратором»** (AppLocker / политика компании) — запуск неподписанных программ
  запрещён политикой; обходить её не стоит — спроси ИТ, из какой папки разрешено запускать программы, или попроси добавить
  исключение. Вариант, если на компьютере разрешён .NET SDK: собрать и запустить из исходников
  (см. [для разработчика](TicketBoard/README.md)).
- **Антивирус ругается** — самодостаточные неподписанные exe иногда ложно помечаются. Можно проверить файл на
  [virustotal.com](https://www.virustotal.com) и добавить в исключения.

### Хоткей не работает
В трее появится уведомление «Хоткей не работает» — сочетание занято другой программой. Поменяй его в настройках.

### Ошибки Интрасервиса
| Сообщение | Что значит |
|---|---|
| неверный логин или пароль | проверь логин/пароль; или сервер перенаправил http → https — впиши адрес с `https://` |
| нет доступа | у пользователя нет прав на эту заявку или на API |
| заявка не найдена | нет заявки с таким номером (или регулярка вытащила из ссылки не тот номер) |
| сервер недоступен | неверный адрес, нет сети или VPN. Под сообщением — причина из Windows: «No such host is known» — адрес не тот, «SSL connection could not be established» — сертификат |
| сервер не ответил за 10 с | сервер перегружен или недоступен (страница списка при выгрузке ждёт 60 с; выгрузка сама повторяет такой запрос) |
| соединение оборвалось | ответ начал приходить и прервался — сеть, VPN или прокси. Под сообщением — причина из Windows |
| ошибка сервера (HTTP 5xx) | сервер Интрасервиса сам сломался на этом запросе. Под сообщением — что он ответил |
| ошибка сервера (HTTP 400) | сервер не принял какой-то параметр запроса — под сообщением, какой (`"errors": {…}`). Это ошибка программы, а не ваша: пришлите текст |
| непонятный ответ сервера | ответ пришёл, но в неожиданной форме. Под сообщением — **сам ответ сервера**, как есть (html-страницу показываем её текстом). Его можно выделить мышью и скопировать (в окне-сообщении: щёлкнуть по тексту, `Ctrl+A`, `Ctrl+C`). Полный ответ ещё и в `errors.log` |
| API не настроен | не заполнены адрес, логин или пароль в настройках |

### Claude не получает ответ
| Что видно | Что делать |
|---|---|
| после **Copy** нет уведомления «Ответ для Claude — в буфере» | галочка в Настройки → Claude не стоит, TicketBoard не запущен, или в блоке есть строка не с `TB` — попроси Claude повторить блок только из запросов |
| в ответе «API Интрасервиса не настроен» | заполни адрес, логин и пароль в настройках |
| в ответе «Не понял запрос» | Claude написал запрос не по форме — он увидит это в ответе и поправится сам |
| уведомление «Ответ для Claude не попал в буфер» | буфер держала другая программа — нажми **Copy** на блоке ещё раз |
| Claude не пишет блоки `TB`, а просит найти самому | инструкция не вставлена: Настройки → Claude → **Скопировать инструкцию для Claude** |

### Obsidian Git не отправляет базу

Пишет, что файл больше 100 МБ (`exceeds GitHub's file size limit`) или про `unknown Git LFS object`, — в хранилище не
включён Git LFS, и крупное вложение из `files-lfs` попало в коммит как есть. Выполните в папке хранилища
`git lfs install`; уже сделанный коммит с таким файлом переводят в LFS командой `git lfs migrate import` (см. справку
Git LFS) — до того отправка стоит. Следующие крупные файлы пойдут через LFS сами: правило в `.gitattributes` уже есть.

### Приложение показало окно с ошибкой
Ошибки API показываются с тем, что сервер ответил на самом деле: первой строкой — коротко по-русски и код HTTP
(«неверный логин или пароль (HTTP 401)»), ниже — тело ответа сервера (логин и пароль из него вычищаются) или причина
сетевой ошибки («сервер недоступен:
No such host is known»). Текст можно выделить и скопировать. Всё это, а также падения приложения, ещё и пишется
в `errors.log` рядом с exe.
